# Release & Deployment Script Guide

## Overview

The `scripts/release-version.sh` script automates the entire process of adding a new Spark/Livy version and deploying it to your Kubernetes cluster.

## What It Does

The script performs the following steps automatically:

1. **Updates `scripts/generate-overlays.sh`** - Adds new version to VERSIONS array
2. **Generates Kustomize overlays** - Creates version-specific kustomization.yaml files
3. **Validates overlays** - Tests Kustomize configuration
4. **Deploys to Kubernetes** - Optional deployment with confirmation
5. **Verifies deployment** - Confirms pod is running with correct version

## Usage

### Basic Syntax

```bash
./scripts/release-version.sh [spark_version] [livy_version] [--deploy]
```

### Usage Examples

#### 1. Interactive Mode (Prompts for Versions)
```bash
./scripts/release-version.sh
# Will prompt you to enter Spark and Livy versions
```

#### 2. Generate Overlays Only (No Deployment)
```bash
./scripts/release-version.sh 4.0.0 0.9.0
# Creates overlays but doesn't deploy
# You'll see the deployment command to run manually if needed
```

#### 3. Generate and Deploy Immediately
```bash
./scripts/release-version.sh 4.0.0 0.9.0 --deploy
# Generates overlays, tests them, and deploys to Kubernetes
# Will ask for confirmation before deploying
```

#### 4. Help
```bash
./scripts/release-version.sh --help
```

## Example Workflow

```bash
# Add Spark 4.0.0 + Livy 0.9.0
./scripts/release-version.sh 4.0.0 0.9.0

# Output shows:
# ✅ Updated scripts/generate-overlays.sh
# ✅ Generated overlays
# ✅ Kustomize overlay validation passed
# 
# Next steps:
#   Deploy: kubectl apply -k k8s/overlays/spark-4.0.0/
#   Test: ./scripts/test-livy.sh

# Then deploy when ready
kubectl apply -k k8s/overlays/spark-4.0.0/

# Or use --deploy flag for automatic deployment
./scripts/release-version.sh 4.0.0 0.9.0 --deploy
```

## What Files Get Created/Modified

### Files Created
- `k8s/overlays/spark-X.Y.Z/kustomization.yaml` - Version-specific overlay

### Files Modified
- `scripts/generate-overlays.sh` - Updated with new version

### Files Left Unchanged
- `k8s/base/` - Always version-agnostic
- Docker images - Not built by this script (use `./build-image.sh` first)

## Generated Overlay Files

Each generated overlay includes:
- ✅ Image tag override (Spark X.Y.Z)
- ✅ ConfigMap patches for pod templates
- ✅ Version labels for tracking
- ✅ Auto-generated warning comment (don't edit directly)

```yaml

apiVersion: kustomize.config.k8s.io/v1beta1

# ...
```

## Safety Features

1. **Version Validation** - Checks X.Y.Z format
2. **Duplicate Detection** - Warns if version already exists
3. **Deployment Confirmation** - Asks before deploying to production
4. **Kustomize Validation** - Tests overlay before deployment
5. **Deployment Cleanup** - Deletes old Deployment before applying new one (resets immutable selector fields)
6. **Rollout Status Check** - Verifies pod is ready before considering success
7. **Namespace Check** - Verifies target namespace exists

## Troubleshooting

### Script fails: "Invalid version format"
- Check your version is in X.Y.Z format (e.g., 3.5.7, not 3.5)

### Script fails: "Namespace 'spark-livy' does not exist"
- Create namespace first: `kubectl create namespace spark-livy`

### Overlay generation failed
- Check `scripts/generate-overlays.sh` syntax
- Verify VERSIONS array format: `["spark_version"]="livy_version"`

### Deployment failed
- Check pod status: `kubectl -n spark-livy get pods`
- Check logs: `kubectl logs -n spark-livy deployment/spark-livy`
- Ensure image exists: `docker images | grep stedoh/spark-livy`

## Reverting a Deployment

If deployment fails, revert to previous version:

```bash
# Deploy previous version
./scripts/release-version.sh 3.5.7 0.8.0 --deploy

# Or manually
kubectl apply -k k8s/overlays/spark-3.5.7/
kubectl rollout restart deployment/spark-livy -n spark-livy
```

## Integration with CI/CD

The script can be used in CI/CD pipelines:

```bash
#!/bin/bash
set -e

# Build image first
./build-image.sh 4.0.0 0.9.0

# Release version (without immediate deployment)
./scripts/release-version.sh 4.0.0 0.9.0

# Test in staging
kubectl apply -k k8s/overlays/spark-4.0.0/ -n spark-livy-staging

# Run tests
./scripts/test-livy.sh

# Promote to production (with approval)
./scripts/release-version.sh 4.0.0 0.9.0 --deploy
```

## FAQ

**Q: Do I need to run `build-image.sh` first?**
A: Yes, the Docker image must be built and available before using release-version.sh

**Q: Can I add multiple versions at once?**
A: Run the script separately for each version, or edit `generate-overlays.sh` directly and run `./generate-overlays.sh`

**Q: What if I make a mistake in the version?**
A: The script handles duplicates and will warn you. Edit `scripts/generate-overlays.sh` to fix and rerun

**Q: How do I remove a version?**
A: Edit `scripts/generate-overlays.sh`, remove the version line, and run `./scripts/generate-overlays.sh`

**Q: Can I test the overlay without deploying?**
A: Yes, generate without `--deploy` flag and manually test: `kubectl kustomize k8s/overlays/spark-X.Y.Z/`
